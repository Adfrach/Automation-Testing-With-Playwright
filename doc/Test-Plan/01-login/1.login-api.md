# Test Plan API - 01 Login (OrangeHRM)

> **Fitur:** Login / Authentication
> **Mode:** API
> **Environment:** development
> **Base URL:** `https://opensource-demo.orangehrmlive.com`
> **Total Test Cases:** 8
> **Tagging:** @smoke / @regression

---

## Informasi Endpoint

| Method | Endpoint | Tujuan |
|--------|----------|--------|
| POST | `{BASE_URL}/web/index.php/auth/validate` | Validasi kredensial login & set session |
| GET | `{BASE_URL}/web/index.php/dashboard/index` | Endpoint dashboard (terautentikasi) |
| GET | `{BASE_URL}/web/index.php/core/i18n/messages` | (Opsional) muat i18n messages |

> Referensi detail request/response: eksplorasi langsung pada aplikasi (html form + network).
> Login menggunakan `application/x-www-form-urlencoded` dengan field `username`, `password` (+ CSRF token).

---

> **PENTING (temuan eksplorasi):** `POST /auth/validate` **menolak akses via HTTP API murni** — endpoint ini hanya bekerja dalam session UI penuh (SPA). Maka:
> - **Login valid** dibentuk melalui **alur UI browser** → simpan `storageState` (session cookie).
> - **API test untuk akses terautentikasi** memakai `storageState` tersebut.
> - **Skenario negatif** `POST /auth/validate` dipakai untuk memastikan sistem **tidak** redirect ke dashboard saat kredensial/token tidak valid.

---

## Skenario Test

### TC-01 - Login berhasil via UI & session dapat dipakai API (Happy Path) — @smoke @regression

**Gherkin:**
- Given user melakukan login valid via browser UI (kredensial `Admin`/`admin123`)
- When session (`storageState`) tersimpan
- Then request API ke `/web/index.php/dashboard/index` dengan session tsb → response `200`

**Expected step-by-step:**
1. Login via UI → redirect ke `/web/index.php/dashboard/index`.
2. Simpan `storageState` (cookie session).
3. Gunakan request context dengan `storageState` tsb → GET `/dashboard/index`.
4. Status `200` (session diterima, bukan redirect ke login).

### TC-02 — Login gagal karena password salah — @regression
**Steps:**
1. `POST /auth/validate` dgn `username=Admin`, `password=wrongpassword` (tanpa session UI valid).
2. Verifikasi respons **tidak** redirect ke dashboard — tetap `/auth/login`.
3. Status `200` dengan body halaman login (tidak ada session dashboard).

### TC-03 — Login gagal karena username salah — @regression
**Steps:**
1. `POST /auth/validate` dgn `username=WrongUser` & `password=admin123`.
2. Tidak redirect ke dashboard, tetap `/auth/login`.

### TC-04 — Login dengan username kosong — @smoke @regression
**Steps:**
1. `POST /auth/validate` dgn `username=` & `password=admin123` (tanpa token valid).
2. Sistem menolak, tetap `/auth/login`.

### TC-05 — Login dengan password kosong — @smoke @regression
**Steps:**
1. `POST /auth/validate` dgn `username=Admin` & `password=` (empty).
2. Sistem menolak, tidak redirect ke Dashboard.

### TC-06 — Login dengan kredensial kosong (keduanya) — @regression
**Steps:**
1. `POST /auth/validate` dgn `username=` & `password=` (keduanya kosong).
2. Sistem menolak, tetap `/auth/login`.

### TC-07 — Login dengan payload JSON — @regression
**Steps:**
1. `POST /auth/validate` dengan `Content-Type: application/json` & body `{"username":"Admin","password":"admin123"}`.
2. Verifikasi sistem menolak body yang tidak sesuai (form-urlencoded diharuskan).

### TC-08 — Akses endpoint terautentikasi TANPA session → ditolak — @smoke @regression
**Steps:**
1. Request `GET /web/index.php/dashboard/index` **tanpa** storageState/session.
2. Verifikasi sistem tidak mengembalikan konten dashboard (redirect ke `/auth/login` atau halaman login).
3. Status `200` + body berupa halaman login (bukan dashboard).
